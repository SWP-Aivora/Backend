Architecture Review: Aivora Backend

Identifying and resolving architectural friction through deep modules and locality.

1. Unified Project Lifecycle

Strong Recommendation

Problem

Project status transitions are fragmented across 6+ services. Treasury owns completion logic but incorrectly ignores REFUNDED milestones, causing projects to hang in ACTIVE status. Callers must manually coordinate multiple state changes, leading to brittle invariants.

Solution

Consolidate all project/milestone state transitions into a single Deep Module (Deep Treasury). This module will expose high-leverage methods like FinalizeMilestoneSettlement that handle status, payments, and project completion atomically.

Benefits: High Locality for project completion logic. Callers get Leverage by not needing to know how to resolve a project status.

Affected: Treasury.cs, MilestoneService.cs, DisputeService.cs

2. Dispute Consolidation

Worth Exploring

Problem

OpenDisputeAsync is implemented twice (in MilestoneService and DisputeService) with different logic. MilestoneService manually freezes funds, while DisputeService uses Treasury, creating an inconsistent audit trail.

Solution

Collapse the duplicated logic into a single Deep Dispute Module. Move the payment freezing logic exclusively into Treasury and ensure the DisputeService is the sole authority for dispute lifecycle state transitions.

3. AI-to-Job Integrity

Speculative

Problem

AI suggests professional milestones, but AcceptSuggestionAsync drops them because the JobPost entity doesn't support milestones. This is a Leaky Seam where domain data evaporates between stages.

Solution

Enhance JobPost to support "Plan Milestones" (Draft Milestones). Modify AcceptSuggestionAsync to persist these, ensuring the AI-driven planning phase actually informs the downstream proposal process.

Top Recommendation

Unified Project Lifecycle

Consolidating the fragmented status transitions in Treasury provides the highest architectural ROI. It fixes a known bug (project completion) and removes the cognitive load of coordinating 6 different services for a single concept.
